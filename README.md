# Buddy Loop

**AI Buddy ที่ดูแลสินค้าเดิมและสร้างสินค้าใหม่ให้แบรนด์ retail แบบอัตโนมัติ** — เดโมจาก Bizbuddy

Buddy Loop ทำงานเป็น 2 เลนพร้อมกัน โดยมีสมองกลางตัวเดียว

| เลน | ทำอะไรเองทุกวัน |
|---|---|
| **Run · ของเดิม** | forecast รวม Shopee/TikTok Shop/Lazada · สั่งผลิต OEM · ตั้งโปรก่อนแคมเปญโดยไม่ต่ำกว่ามาร์จินขั้นต่ำ · ย้ายงบแอดไปช่องที่ ROAS สูง · หยุดแอดเมื่อของใกล้หมด · เคลียร์ของค้างตามกติกา · ตอบรีวิวและแชท |
| **Grow · ของใหม่** | จับเทรนด์ → สัมภาษณ์ลูกค้าจริง → จับคู่ OEM ล็อตเล็ก → เปิดพรีออเดอร์ทดสอบ 14 วัน → ตัด/ปรับ/ขยายเอง → ตัวที่ผ่านกลายเป็น SKU ใหม่ใน Run |
| **Learn · สมองกลาง** | รวมรีวิว การคืนสินค้า แชท และผลทดสอบ · ปัญหาซ้ำของสินค้าเดิมกลายเป็นไอเดีย "ปรับของเดิม" ใน Grow เอง · สรุปบทเรียนทุกสัปดาห์ |

เจ้าของเห็นเฉพาะ **Inbox ข้อยกเว้น** คือเรื่องที่เกินกรอบที่ตั้งไว้ (PO ใหญ่ งบทดสอบเกินเพดาน คืนเงินก้อนใหญ่ การเปิดตัวสินค้า) ที่เหลือ Buddy ทำเอง ตัวชี้วัดหลักคือ **Automation rate** (เป้า ≥ 90%)

> เดโมนี้จำลองตลาดในเบราว์เซอร์ด้วยแบรนด์สมมติ "Mira Skin" ตัวเลขทั้งหมดเป็นตัวอย่าง ตรรกะการตัดสินใจของทุกเครื่องยนต์เป็นของจริง และนำเข้าข้อมูลสินค้า/รีวิวของแบรนด์จริงได้

---


ข้อมูลทั้งหมดเก็บใน `localStorage` ของเบราว์เซอร์ ปิดแล้วเปิดใหม่ยังอยู่ กด "เริ่มเดโมใหม่" ในแท็บ **ข้อมูล & AI** เพื่อล้าง


## 3. วิธีเดโม (สรุป)

สคริปต์ฉบับเต็มสำหรับนำเสนอ 11 นาทีอยู่ที่ [`docs/DEMO-SCRIPT.md`](docs/DEMO-SCRIPT.md)

1. **วันนี้** — ชี้ Automation rate และ Inbox ข้อยกเว้น ("ทั้งวันมีแค่นี้ที่ต้องใช้คุณ")
2. กด **รัน 1 วัน** — ดูบันทึกการทำงาน แยก Run / Grow / Learn
3. อนุมัติ PO ใหญ่ 1 ใบ และเปิดตัวสินค้า 1 ตัว
4. **Run** — คลิก "โทนเนอร์" ให้เห็นว่ารีวิว "แสบ" ถูกส่งเป็นไอเดียปรับสูตร
5. **Grow** — เปิดการ์ดในขั้นทดสอบ ชี้เกณฑ์ตัด/ขยายที่ตั้งไว้ก่อน แล้วกด **Product brief**
6. **Learn** — กด **สรุปรอบถัดไปให้ strategist**
7. **กติกา** — เปลี่ยน Launch เป็น "ทำเอง" แล้วกด **30 วัน** ให้เห็นระบบเดินเอง
8. **Playbook** — ชี้ว่าแบรนด์ถัดไปใช้ระบบเดิมได้ทันที onboard ใน 7 วัน
9. กด **Autopilot** ปล่อยให้ระบบวิ่งระหว่างคุยต่อ

## 4. ใช้กับข้อมูลจริงของแบรนด์

แท็บ **ข้อมูล & AI** → นำเข้า CSV (ไฟล์ตัวอย่างอยู่ใน `data/`)

**สินค้า** `data/products-template.csv`

| คอลัมน์ | บังคับ | ความหมาย |
|---|---|---|
| sku, name | ✓ | รหัสและชื่อสินค้า |
| price, cost | ✓ | ราคาขายปกติ และต้นทุนต่อชิ้น (บาท) |
| stock | ✓ | สต็อกพร้อมขายตอนนี้ |
| daily_sales | ✓ | ขายเฉลี่ยต่อวัน (ชิ้น) รวมทุกช่องทาง |
| lead_time_days, moq | | เวลาผลิตของ OEM และขั้นต่ำต่อการสั่ง (ค่าเริ่มต้น 21 วัน / 300 ชิ้น) |
| category, age_days, rating, oem | | หมวด อายุสินค้า คะแนนรีวิว ชื่อ OEM |
| roas_shopee, roas_tiktok, roas_lazada | | ROAS ปัจจุบันของแต่ละช่องทาง |
| ad_shopee, ad_tiktok, ad_lazada | | งบแอดต่อวันของแต่ละช่องทาง (บาท) |

**รีวิว / แชท / การคืนสินค้า** `data/reviews-template.csv` — คอลัมน์ `sku, rating, text`
Buddy จัดกลุ่มปัญหาจากคำในข้อความ (เช่น แสบ ระคาย เหนียว แห้ง กลิ่นแรง รั่ว) ถ้าปัญหาเดียวกันซ้ำ ≥ 3 ครั้งใน 14 วัน จะสร้างไอเดีย "ปรับของเดิม" ใน Grow ทันที

ได้ข้อมูลจากไหน
- Shopee Seller Centre → ข้อมูลธุรกิจ / สินค้า → Export
- ZORT → รายงานสต็อก → Export Excel แล้วบันทึกเป็น CSV (UTF-8)
- รีวิว: export จาก Seller Centre หรือคัดลอกจากหน้ารีวิวลง Google Sheets แล้วดาวน์โหลดเป็น CSV

ข้อควรรู้เรื่อง PDPA: ลบชื่อและข้อมูลส่วนบุคคลของผู้รีวิวออกก่อนนำเข้า Buddy ใช้แค่ข้อความและคะแนน

## 4.1 ทำซ้ำกับแบรนด์ถัดไปด้วย Playbook

แท็บ **Playbook**
- **ส่งออก playbook** ได้ไฟล์ JSON ที่มีกติกา ประตูตัดสิน เครือข่าย OEM รายการเทรนด์ และ benchmark แบบไม่ระบุแบรนด์ (ไม่มีสินค้า รีวิว หรือยอดขาย)
- **เริ่มแบรนด์ใหม่** ใส่ชื่อแบรนด์ เลือก playbook (ที่ใช้อยู่ / Beauty / อาหารเสริม) แล้วนำเข้าสินค้าและรีวิวของแบรนด์ใหม่
- **Onboarding checklist** 5 ขั้น เป้าหมายครบภายใน 7 วัน แบรนด์ใหม่เริ่มในโหมดระมัดระวัง 7 วัน แล้วกดเปลี่ยนเป็นระดับอัตโนมัติของ playbook
- **นำเข้า playbook** ไฟล์ JSON ที่ส่งออกจากแบรนด์อื่น เพื่อใช้กติกาและ benchmark ล่าสุด

เดโมเก็บได้ครั้งละ 1 แบรนด์ต่อเบราว์เซอร์ ก่อนเริ่มแบรนด์ใหม่ให้กด **สำรองทั้งหมด (JSON)** ในแท็บข้อมูล แล้วกู้คืนภายหลังได้ เวอร์ชัน production เก็บหลายแบรนด์บน backend โดยข้อมูลของแต่ละแบรนด์แยกกัน

## 5. เชื่อม Claude ให้ AI เขียนเอกสารจริง (ไม่บังคับ)

แท็บ **ข้อมูล & AI** → ใส่ Anthropic API key → บันทึก → **ทดสอบการเชื่อมต่อ**
เมื่อเชื่อมแล้ว ปุ่มเหล่านี้จะใช้ Claude แทนเทมเพลต
- Grow → Product brief / สคริปต์สัมภาษณ์ลูกค้า / หน้า listing พรีออเดอร์
- Learn → สรุปรอบถัดไปให้ strategist (Loop Review)

ค่าเริ่มต้นใช้โมเดล `claude-sonnet-5-5` (เปลี่ยนเป็น `claude-haiku-5-5` ได้ถ้าต้องการเร็วและถูก)

**ความปลอดภัย:** หน้าเว็บเรียก API จากเบราว์เซอร์โดยตรง (header `anthropic-dangerous-direct-browser-access`) key จึงอยู่ในเบราว์เซอร์ของผู้ใช้ เหมาะกับการเดโมด้วย key ส่วนตัวที่ตั้งวงเงินต่ำเท่านั้น สำหรับใช้งานจริงให้ย้ายการเรียก API ไปไว้ที่ backend

## 6. กติกาและระดับอัตโนมัติ

ทุกเครื่องยนต์ตั้งได้ 3 ระดับในแท็บ **กติกา**: `ทำเอง` · `ขออนุมัติ` · `ปิด`
ชุดสำเร็จรูป: **อัตโนมัติสูงสุด** · **ระมัดระวัง** (ขออนุมัติ PO, โปร, งบทดสอบ, เปิดตัว) · **ค่าเริ่มต้น**

| กติกา | ค่าเริ่มต้น | ใช้กับ |
|---|---|---|
| มาร์จินขั้นต่ำหลังลดราคา | 25% | Price & Promo |
| ส่วนลดสูงสุด | 40% | ทุกโปร |
| งบแอดรวมต่อวัน | ฿9,000 | Ads |
| PO เกินนี้ต้องอนุมัติ | ฿100,000 | Replenish |
| สต็อกกันชน | 14 วัน | Replenish |
| คืนเงินอัตโนมัติไม่เกิน | ฿1,000 | Service |
| เคลียร์สต็อก | 60 / 90 / 120 วันขาย → bundle / flash / outlet | Clearance |
| หลักฐานขั้นต่ำ / คะแนนสัมภาษณ์ | 60 / 60 | Sense / Ask |
| งบทดสอบต่อไอเดีย | ฿15,000 | Make |
| ทดสอบ | 14 วัน · ขยาย ≥ 2.5% · ตัด ≤ 0.8% | Test |

ตรรกะที่ทำให้ "อัตโนมัติแต่ไม่เสี่ยง"
- **PO ใหญ่ที่รอคุณเกิน 2 วัน** และของจะหมดก่อนของใหม่มา → Buddy สั่ง "ล็อตฉุกเฉิน" ที่ไม่เกินเพดานเอง ส่วนที่เหลือยังรอคุณ
- **ของเหลือ < 7 วัน** → หยุดแอดของ SKU นั้นทันที (ไม่จ่ายเงินดึงคนมาเจอของหมด) และไม่ร่วมแคมเปญ
- **โปรแคมเปญ** อุ่นล่วงหน้า 3 วัน ลดได้เท่าที่มาร์จินยังไม่ต่ำกว่าเกณฑ์ ถ้าลดไม่ได้จะเปลี่ยนเป็น bundle
- **ทดสอบขาย** ตัดเร็วที่วันที่ 7 ถ้าแย่กว่าครึ่งของเกณฑ์ตัด คืนเงินพรีออเดอร์พร้อมคูปองสินค้าเดิม ผลกลาง ๆ ให้ปรับแล้วทดสอบซ้ำได้ 1 รอบ
- **ลูกค้าจำลอง** ใช้จัดอันดับเท่านั้น การตัดสินใจมาจากการสัมภาษณ์ลูกค้าจริงและยอดพรีออเดอร์จริง

## 8. จากเดโมสู่ระบบใช้งานจริง

| ส่วน | เดโม | Production |
|---|---|---|
| ข้อมูลยอดขาย/สต็อก | จำลอง / CSV | Shopee Open Platform, TikTok Shop Partner API, Lazada Open Platform, ZORT |
| ราคา โปร flash sale voucher | จำลอง | Shopee discount/voucher/flash sale API, TikTok Shop promotion API |
| แอด | จำลอง | Shopee Ads API, Meta Marketing API · TikTok GMV Max และ Lazada ads ตั้งโดย strategist ก่อน |
| รีวิว / แชท | CSV | review API ของแต่ละ marketplace, LINE Messaging API |
| สัมภาษณ์ลูกค้า | จำลองคะแนน | LINE OA bot + Claude + Thai speech-to-text |
| PO ถึง OEM | บันทึก | LINE / อีเมลพร้อมปุ่มยืนยัน |
| เทรนด์ | รายการตัวอย่าง | Google Trends API (alpha) + พาร์ตเนอร์ข้อมูลที่มีไลเซนส์ |
| การทำงานรายวัน | ปุ่มรัน | backend + cron (เช่น Cloud Run/Workers) เรียก `engine` ทุกคืน แล้วแจ้ง Inbox ทาง LINE |

`js/engine.js` เขียนแยกจากหน้าจอไว้แล้ว ย้ายไปรันบน Node ฝั่ง server ได้ทันที เปลี่ยนแค่ส่วนจำลองตลาด (`simulateProduct`) เป็นการอ่านข้อมูลจริงจาก API และเปลี่ยน `log(...)` ของแต่ละการกระทำเป็นการเรียก API จริง
