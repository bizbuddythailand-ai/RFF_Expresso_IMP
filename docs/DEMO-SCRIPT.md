# สคริปต์เดโม Buddy Loop · 11 นาที

สำหรับ strategist ของ Bizbuddy เวลานำเสนอเจ้าของแบรนด์หรือกรรมการ

## ก่อนเริ่ม (2 นาทีก่อนเข้าห้อง)
- เปิดลิงก์ GitHub Pages ใน Chrome แล้วไปแท็บ **ข้อมูล & AI** → **เริ่มเดโมใหม่** เพื่อให้ทุกครั้งเริ่มจากสถานะเดียวกัน
- (ไม่บังคับ) ใส่ Claude API key แล้วกด **ทดสอบการเชื่อมต่อ** ถ้าเน็ตไม่แน่นอน ไม่ต้องใส่ เทมเพลตในตัวพอสำหรับเดโม
- ซูมเบราว์เซอร์ 110–125% ถ้าฉายจอใหญ่

## 0:00 – 1:00 · ตั้งโจทย์
> "เจ้าของแบรนด์ทุกคนมีข้อมูลครบ แต่ไม่มีเวลาลงมือ ของเดิมต้องเติมสต็อก ตั้งโปร ตอบรีวิวทุกวัน ส่วนของใหม่ก็ต้องเดาว่าจะออกอะไร Buddy Loop ทำทั้งสองขาให้ โดยคุณตั้งกติกาครั้งเดียว"

## 1:00 – 2:30 · แท็บ "วันนี้"
- ชี้ **Automation rate** (~95%): "งานเกือบทั้งหมด Buddy ทำเอง"
- ชี้ **Inbox ข้อยกเว้น**: "นี่คือทั้งหมดที่ต้องใช้คุณวันนี้" อ่านเหตุผลบรรทัด **ทำไมมาถึงคุณ** ของ PO ใบใหญ่สุด
- กด **อนุมัติ** 1 ใบ แล้วกด **ไม่อนุมัติ** อีก 1 ใบ ให้เห็นว่าคุมได้จริง

## 2:30 – 4:00 · รันวันใหม่
- กด **รัน 1 วัน** → ชี้ toast "Buddy ทำเอง X งาน"
- ในบันทึกการทำงาน กดตัวกรอง **Run** → ชี้ตัวอย่าง: ย้ายงบแอดไป TikTok, ตอบรีวิว, คืนเงินเล็ก ๆ อัตโนมัติ
- กดตัวกรอง **ที่ใช้คน** → "สัปดาห์หนึ่งมีไม่กี่เรื่อง"

## 4:00 – 5:30 · Run · ของเดิม
- คลิกแถว **โทนเนอร์** → เลื่อนดู "ลูกค้าพูดถึง" มี "แสบ/ระคายเคือง"
- ด้านขวาชี้บรรทัด **เจอปัญหาซ้ำ** → "รีวิวไม่ได้จบที่ dashboard มันกลายเป็นงานพัฒนาสินค้าเอง"
- คลิกสินค้าที่สถานะ **ค้างสต็อก** → ชี้ bundle/flash sale ตามกติกา 60/90/120 วัน

## 5:30 – 7:30 · Grow · ของใหม่
- ชี้ 6 คอลัมน์ และป้าย **ของใหม่ / ปรับของเดิม**
- คลิกการ์ดในคอลัมน์ **ทดสอบขาย** → ชี้ "ตัด ≤ 0.8% · ขยาย ≥ 2.5%" ที่ตั้งไว้ก่อนเริ่ม
  > "เราไม่ผลิตทั้งล็อตก่อนรู้ ทดสอบด้วยเงินจริง 14 วัน ตัวไม่ผ่านถูกตัดตั้งแต่ล็อตเล็ก"
- กด **Product brief** (และ **สคริปต์สัมภาษณ์ลูกค้า** ถ้ามีเวลา)
- คอลัมน์ **ตัดทิ้ง**: "ตัวที่ถูกตัดคือเงินที่ประหยัดได้"

## 7:30 – 8:30 · Learn
- ชี้กราฟปัญหาที่ลูกค้าพูดถึง และ Learn ledger
- กด **สรุปรอบถัดไปให้ strategist** → "นี่คือเอกสารที่เราใช้ใน Loop Review ทุก 90 วัน"

## 8:30 – 9:30 · ให้ระบบวิ่งเอง
- แท็บ **กติกา** → เปลี่ยน **เปิดตัว** เป็น "ทำเอง" (หรือกด **อัตโนมัติสูงสุด**)
- กด **30 วัน** → กลับแท็บ **วันนี้** ชี้ยอดขายจาก SKU ใหม่ และกราฟที่มีแท่งสีส้มเพิ่มขึ้น
- กด **Autopilot** ปล่อยไว้ระหว่างตอบคำถาม

## 9:30 – 10:30 · ทำซ้ำได้กับแบรนด์ถัดไป
- แท็บ **Playbook** → ชี้ว่า playbook มีแค่กติกา OEM เทรนด์ และ benchmark ไม่มีข้อมูลของแบรนด์
- ชี้ checklist **Onboarding** 5 ขั้น เป้าหมายครบใน 7 วัน
- (ถ้ามีเวลา) ใส่ชื่อแบรนด์ใหม่ เลือก playbook **อาหารเสริม** → **เริ่มแบรนด์ใหม่** → นำเข้าสินค้าตัวอย่างในแท็บข้อมูล → **รัน 7 วัน**
  > "แบรนด์ที่สองไม่ต้องเริ่มจากศูนย์ ระบบเดิม กติกาเดิม แค่ใส่ข้อมูลของเขา"
- ก่อนสลับแบรนด์ ให้กด **สำรองทั้งหมด (JSON)** ไว้ เพื่อกู้แบรนด์ Mira Skin กลับมาได้

## 10:30 – 11:00 · ปิด
> "เริ่มจาก S-Curve Lab Sprint 90 วัน เราเอาข้อมูลจริงของแบรนด์ใส่ระบบนี้ หาตัวชนะ 1 ตัว แล้วให้ Buddy ดูแลต่อทั้งของเดิมและของใหม่ และทุกอย่างที่เรียนรู้กลายเป็น playbook ที่ใช้กับแบรนด์ถัดไปได้ทันที"

## คำถามที่มักเจอ
| คำถาม | คำตอบ |
|---|---|
| ใช้กับข้อมูลเราได้ไหม | ได้ แท็บข้อมูล นำเข้า CSV สินค้าและรีวิว ระบบเริ่มตัดสินใจจากข้อมูลนั้นทันที |
| ถ้า AI ตั้งราคาผิด | ทุกโปรถูกล็อกด้วยมาร์จินขั้นต่ำและส่วนลดสูงสุด และตั้งให้ขออนุมัติรายเครื่องยนต์ได้ |
| ลูกค้าจำลองเชื่อได้ไหม | ใช้แค่จัดอันดับ ตัดสินด้วยสัมภาษณ์ลูกค้าจริงและยอดพรีออเดอร์จริงเสมอ |
| ข้อมูลลูกค้าปลอดภัยไหม | เดโมเก็บในเบราว์เซอร์เท่านั้น เวอร์ชันจริงตัดข้อมูลส่วนบุคคลก่อนวิเคราะห์ และไม่ใช้ข้อมูลลูกค้าเทรนโมเดล |
| ผูกกับลูกค้ารายเดียวไหม | ไม่ ทุกอย่างที่ใช้ซ้ำได้อยู่ใน playbook ของหมวด แบรนด์ถัดไป onboard ได้ใน 7 วัน ข้อมูลของแต่ละแบรนด์แยกกันและไม่ถูกแชร์ |
| ต่อกับ Shopee/TikTok จริงเมื่อไหร่ | เฟส 6 เดือนแรก: Shopee API + ZORT ก่อน TikTok Shop ตามมา แอด TikTok GMV Max ให้ strategist ตั้งเองระหว่างนั้น |
