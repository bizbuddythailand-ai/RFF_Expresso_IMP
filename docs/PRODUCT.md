# Buddy Loop v2 — Product design

> AI Buddy ที่ดูแลธุรกิจทั้งสองขา: **บริการของเดิมให้ขายดีขึ้นทุกวัน (Run)** และ **สร้างของใหม่ให้ธุรกิจมี S-Curve ถัดไป (Grow)** โดยมี **Learn** เป็นสมองกลางที่ส่งบทเรียนจากของเดิมไปเป็นไอเดียของใหม่ และส่งตัวที่ชนะจากของใหม่กลับมาเป็นของเดิมที่ระบบดูแลต่อ

## 1. ปัญหาที่ v1 ยังแก้ไม่สุด

| v1 | v2 |
|---|---|
| เน้นสร้างของใหม่ (Grow) อย่างเดียว | ดูแลสินค้าเดิมไปพร้อมกัน เพราะของเดิมคือรายได้ 80–95% ของบริษัท |
| เจ้าของอนุมัติรายวัน | **Autopilot by default** เจ้าของเห็นเฉพาะ *ข้อยกเว้น* ที่เกินกรอบที่ตั้งไว้ |
| Learn เป็นปลายทาง | Learn เป็น **ศูนย์กลาง** รับสัญญาณจากทุกเครื่องยนต์ และสร้างงานให้ทั้งสองเลน |
| strategist ทำหลายขั้นด้วยมือ | strategist ตั้ง "กติกา" ครั้งเดียวต่อรอบ 90 วัน ระบบทำงานเองภายในกรอบ |

## 2. โครงสร้าง: 2 เลน + 1 สมอง

```
            ┌──────────────────────── LEARN (สมองกลาง) ────────────────────────┐
            │  รีวิว · คำค้น · การคืนสินค้า · แชทลูกค้า · ผลทดสอบ · ยอดขาย        │
            └──────┬───────────────────────────────────────────────▲──────────┘
     ปัญหาของเดิม → brief ปรับสูตร/บริการ            ผลจริงทุกวัน │
     เทรนด์/unmet need → concept ใหม่                              │
            ▼                                                     │
  GROW (ของใหม่)                                     RUN (ของเดิม)│
  Sense → Ask → Make → Test → Launch ───ตัวที่ชนะ──▶ Replenish · Price&Promo · Ads
                                                     Clearance · Reviews · Service
```

### RUN — บริการของเดิมให้ดีขึ้นทุกวัน
| เครื่องยนต์ | ทำอะไรเองทุกวัน | กรอบควบคุม (default) |
|---|---|---|
| Replenish | forecast รวม 3 marketplace + แคมเปญที่กำลังมา → ร่าง/ส่ง PO ให้ OEM | PO เกิน ฿100,000 ต้องอนุมัติ · สต็อกกันชน 14 วัน |
| Price & Promo | อุ่นโปรก่อน mega sale 3 วัน, Payday, หยุดโปรเมื่อของใกล้หมด | มาร์จินขั้นต่ำ 25% · ลดสูงสุด 40% |
| Ads | ย้ายงบไปช่องที่ ROAS สูงทุกสัปดาห์ · หยุดแอด SKU ที่ของเหลือ < 7 วัน | งบแอดรวมต่อวันไม่เกินเพดาน |
| Clearance | ของเหลือเกิน 60/90/120 วันขาย → bundle / flash sale / outlet | ไม่ขายต่ำกว่าทุน |
| Reviews | ตอบรีวิวทุกชิ้น · จัดกลุ่มปัญหา · ปัญหาซ้ำ ≥ 3 ใน 14 วัน → ส่ง brief ปรับสินค้าเดิมเข้า Grow | ตัดข้อมูลส่วนบุคคล (PDPA) |
| Service | ตอบแชทคำถามทั่วไป · ส่งเคสคืนเงินที่เกินเพดานให้คน | คืนเงินอัตโนมัติไม่เกิน ฿1,000 |

### GROW — สร้างของใหม่ (และ "เวอร์ชันใหม่" ของของเดิม)
| เครื่องยนต์ | ทำอะไรเอง | ประตูตัดสิน |
|---|---|---|
| Sense | ทุก 7 วัน รวมเทรนด์ + ปัญหาจากรีวิว → การ์ด concept พร้อมคะแนนหลักฐาน | หลักฐาน ≥ 60 ไปต่ออัตโนมัติ |
| Ask | AI สัมภาษณ์ลูกค้าจริง 30 คนใน 3 วัน (LINE) + ลูกค้าจำลองจัดอันดับ | คะแนน ≥ 60 ไปต่อ |
| Make | brief, จับคู่ OEM ล็อตเล็ก, ม็อกอัป, listing พรีออเดอร์ | งบทดสอบเกินเพดาน หรือโหมด "อนุมัติ" → ส่งเจ้าของ |
| Test | เปิดพรีออเดอร์ 14 วัน, ตัดเร็วที่วันที่ 7 ถ้าแย่มาก, ปรับแล้วทดสอบซ้ำได้ 1 ครั้ง | ≥ 2.5% ขยาย · ≤ 0.8% ตัด |
| Launch | ของใหม่ → เข้า Run พร้อม PO แรก · ของเดิมสูตรใหม่ → แทนที่ SKU เดิม | การตัดสินใจครั้งเดียวที่ต้องเป็นคน (default) |

ประเภทของ concept ใน Grow
- **new** — สินค้า/บริการใหม่จากเทรนด์และ unmet need
- **improve** — ปรับของเดิม (สูตร แพ็ก บริการ ระบบ) จากปัญหาที่ Reviews/Service เจอ

## 3. ระดับอัตโนมัติ (Autonomy)
ทุกเครื่องยนต์ตั้งได้ 3 ระดับ
- `auto` — ทำเลยภายในกรอบ แจ้งในบันทึก
- `approve` — ร่างให้ แล้วรอเจ้าของแตะอนุมัติใน Inbox
- `off` — ปิด

ค่าเริ่มต้น: ทุกเครื่องยนต์ `auto` ยกเว้น **Launch** (`approve`) และงานที่ "เกินกรอบ" จะกลายเป็น `approve` อัตโนมัติ
ตัวชี้วัดหลักของความเป็น Buddy คือ **Automation rate** = งานที่ทำเองภายในกรอบ ÷ งานทั้งหมด (เป้า ≥ 90%)

## 4. บทบาทคน
| ใคร | ทำอะไร | ความถี่ |
|---|---|---|
| เจ้าของ | เคลียร์ Inbox ข้อยกเว้น (ปกติ 0–3 เรื่อง/วัน) | รายวัน 5 นาที |
| Bizbuddy strategist | ตั้งกติกา, เลือกธีม Grow, ทบทวน Learn ledger | รอบ 90 วัน + รายเดือน |
| AI | ทุกอย่างที่เหลือ | ตลอดเวลา |

## 5. Playbook: ทำซ้ำได้ ไม่ผูกลูกค้ารายเดียว
Buddy Loop ไม่ใช่งาน custom รายลูกค้า ทุกอย่างที่ใช้ซ้ำได้ในหมวดเดียวกันถูกเก็บเป็น **playbook**
- กติกาและประตูตัดสิน (มาร์จินขั้นต่ำ เกณฑ์ทดสอบ ระดับอัตโนมัติ ฯลฯ)
- เครือข่าย OEM ของหมวด
- รายการเทรนด์ที่ต้องเฝ้าดู
- benchmark แบบไม่ระบุแบรนด์ (ค่ากลางพรีออเดอร์ อัตราผ่าน จำนวนการทดสอบ)

ไม่มีสินค้า รีวิว หรือยอดขายของแบรนด์ใดอยู่ใน playbook

**Onboarding แบรนด์ใหม่ ≤ 7 วัน**: เลือก playbook → นำเข้าสินค้า → นำเข้ารีวิว → รัน 7 วันในโหมดระมัดระวัง → เปลี่ยนเป็นระดับอัตโนมัติของ playbook
**ยิ่งลูกค้ามาก ยิ่งแม่น**: ทุกครั้งที่ส่งออก playbook ผลทดสอบของแบรนด์ถูกรวมเข้า benchmark แบบไม่ระบุชื่อ แบรนด์ถัดไปจึงเริ่มด้วยเกณฑ์ที่แม่นขึ้น
เดโมมี playbook ตั้งต้น 2 หมวด: Beauty & personal care และ อาหารเสริม

## 6. Business model (สรุป)
- Run add-on ฿15k/เดือน สำหรับแบรนด์ที่ยังไม่พร้อมทำของใหม่
- S-Curve Lab Sprint ฿180k / 90 วัน (ทางเข้า)
- Loop Partner ฿45k/เดือน + 3% ของ GMV จาก SKU ที่เกิดใน loop (12 เดือน)
- ค่าแนะนำ OEM 3–5%
- ขยายด้วย playbook: strategist 1 คนดูแล 6 แบรนด์ในปีแรก → 15 แบรนด์เมื่อ playbook นิ่ง

ตัวเลขทั้งหมดเป็นสมมติฐานสำหรับทดสอบกับแบรนด์นำร่องชุดแรก (5 แบรนด์ใน 2 หมวด)

## 7. จากเดโมสู่ของจริง
เดโมใน repo นี้จำลองตลาดในเบราว์เซอร์ เพื่อให้เห็นตรรกะการตัดสินใจครบทุกเครื่องยนต์ เวอร์ชัน production ต้องมี backend ที่เชื่อมต่อ
- Shopee Open Platform (สินค้า ราคา โปร flash sale แอด รีวิว)
- TikTok Shop Partner API (โปร ราคา สต็อก รีวิว) — GMV Max ยังตั้งโดยคน
- Lazada Open Platform (สินค้า ราคา สต็อก รีวิว) — แอดยังตั้งโดยคน
- ZORT (สต็อกรวมทุกช่อง)
- LINE Messaging API (แจ้ง Inbox, สัมภาษณ์ลูกค้า, ส่ง PO ให้ OEM)
- Meta Marketing API (แคมเปญทดสอบ)
- Google Trends API (alpha) + พาร์ตเนอร์ข้อมูลที่มีไลเซนส์
